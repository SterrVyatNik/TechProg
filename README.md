# Лабораторная работа № 1 - сбор сведений об ОС

Скрипт определяет, в какой операционной системе он запущен, собирает основные сведения и сохраняет их в файл `os_info.json` рядом со скриптом. Предусмотрена работа в Windows, Linux и macOS.

## Запуск

Нужен Python 3. Внешние библиотеки устанавливать не требуется.

Откройте терминал в папке со скриптом и выполните:

```bash
python my_script.py
```

В Linux и macOS команда для Python 3 часто называется `python3`:

```bash
python3 my_script.py
```

Если в Windows используется Python Launcher, можно выполнить:

```powershell
py my_script.py
```

После запуска скрипт выведет название ОС и путь к результату. При повторном запуске `os_info.json` перезаписывается. Если ОС не поддерживается, не удаётся получить сведения о диске или записать файл, программа выводит сообщение и завершается с кодом 1.

## Собираемые параметры

| Поле JSON | Что означает |
| --- | --- |
| `collected_at` | Дата и время сбора с местным смещением относительно UTC |
| `os.name` | Название ОС: Windows, Linux или macOS |
| `os.version` | В Windows — техническая версия `major.minor.build`; в Linux и macOS — версия ядра |
| `os.architecture` | Архитектура: например, AMD64, x86_64 или arm64 |
| `computer.hostname` | Имя компьютера |
| `computer.logical_cpu_count` | Число логических процессоров, которое возвращает Python |
| `disk.path` | Папка, по которой выбран раздел для проверки |
| `disk.total_bytes` | Общий размер этого раздела в байтах |
| `disk.used_bytes` | Занятое место на этом разделе в байтах |
| `disk.free_bytes` | Свободное место, доступное текущему пользователю, в байтах |
| `python.version` | Версия запущенного интерпретатора Python |

Выбранные параметры показывают сведения об ОС, процессоре и диске и сохраняют понятный объём работы. Время сбора и версия Python помогают понять, когда и в какой среде получен результат.

## Как работает скрипт

1. Проверяет `sys.platform`: `win32` означает Windows, `linux` — Linux, `darwin` — macOS.
2. В Windows получает техническую версию через `sys.getwindowsversion().platform_version`, а архитектуру — из переменных окружения `PROCESSOR_ARCHITEW6432` или `PROCESSOR_ARCHITECTURE`.
3. В Linux и macOS получает версию ядра и архитектуру через `os.uname()`.
4. Получает имя компьютера, число логических процессоров и сведения о разделе со скриптом.
5. Объединяет результаты в словарь и записывает его в JSON.

## Стандартные модули

| Модуль | Для чего используется |
| --- | --- |
| `sys` | Определение ОС, получение технической версии Windows и версии Python, завершение программы при ошибке |
| `os` | Сведения о ядре и архитектуре в Linux/macOS, переменные окружения Windows и число логических процессоров |
| `socket` | Получение имени компьютера |
| `shutil` | Получение сведений о месте на разделе |
| `datetime` | Время сбора данных |
| `pathlib` | Пути к папке скрипта и файлу результата |
| `json` | Запись словаря в JSON |

Внешние модули не использованы: стандартной библиотеки достаточно для выбранных параметров. Скрипт не запускает утилиты ОС и не использует `subprocess`, `os.system()` или `os.popen()`. Вызов `os.uname()` - обращение к системному интерфейсу через Python, а не запуск консольной утилиты `uname`.

## Особенности результата

- В macOS `os.version` содержит версию ядра Darwin, а в Linux - версию ядра Linux. Это не номер выпуска macOS и не версия дистрибутива Ubuntu.
- Техническая версия Windows не равна названию продукта: Windows 11 также может иметь номер версии вида `10.0.<сборка>`.
- В Windows архитектура берётся из окружения процесса. Если нужные переменные отсутствуют, записывается `null`; их ручное изменение может повлиять на результат.
- Число логических процессоров не обязательно равно числу физических ядер. Если Python не может его определить, в JSON будет `null`.
- Сведения о диске относятся к одному разделу со скриптом, а не ко всем накопителям компьютера. В Unix часть места может быть зарезервирована, поэтому `used_bytes + free_bytes` не всегда равно `total_bytes`.
- В виртуальной машине или WSL скрипт описывает среду, в которой запущен Python. Её параметры могут отличаться от параметров основной ОС.

## Проверка перед сдачей

Запустите скрипт в Windows и Linux, откройте полученные файлы `os_info.json` и проверьте, что `os.name` соответствует среде запуска. По возможности повторите проверку в macOS.

В репозиторий достаточно загрузить `my_script.py`, `README.md` и `.gitignore`. Файл `os_info.json` создаётся при запуске и исключён из Git через `.gitignore`.
